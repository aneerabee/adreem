## ما تم تثبيته في هذه الجولة

- تحويل الويب في وضع API إلى cloud-only: لا قراءة دفتر من `localStorage`، لا حفظ دفتر محلي، ولا snapshots محلية في الرابط المنشور.
- حفظ دخول الجهاز في `localStorage` كتذكر دخول طويل الأجل، مع إبقاء بيانات الدفتر نفسها cloud-only بدون قراءة دفتر مالي محلي قديم.
- اختبار رفض API لأي web token غير معروف قبل الوصول لأي دفتر.
- إيقاف قبول web ledger tokens القديمة في API، والاعتماد على session tokens الناتجة من الإيميل وكلمة المرور فقط.
- تحديث فحص التشغيل `verify:runtime` ليسجل الدخول بـ `ADREEM_RUNTIME_TEST_EMAIL/PASSWORD` ثم يختبر `/api/ledger`.
- إضافة اختبار يثبت أن توكنات env القديمة لا تفتح الدفتر.
- إضافة اختبار يثبت أن جلستين مختلفتين تذهبان إلى دفترين منفصلين قبل الوصول إلى repository.
- تقوية API حتى لا يستطيع test repository تجاوز التحقق من token أثناء الاختبارات.
- تحديث متطلبات env على Contabo: إزالة `ADREEM_WEB_LEDGER_*` بالكامل، واستخدام `ADREEM_RUNTIME_TEST_EMAIL/PASSWORD` مع backup وaudit وattachments.
- تصحيح remote السيرفر إلى `https://github.com/aneerabee/adreem.git`.
- تحويل أداة `pnpm ops:create-ledger-access` إلى توافق قديم بدون إنشاء روابط token؛ إنشاء المستخدمين يتم من صفحة الإدارة بالإيميل وكلمة المرور.
- إضافة سجل مستخدمين ديناميكي: صاحب النظام يستطيع إضافة مستخدم مستقل من صفحة إدارة الويب بدون تعديل env في كل مرة.
- المستخدم غير المضاف لا يدخل الدفتر، لكنه يرى رقم تيليغرام الخاص به فقط ليرسله لصاحب النظام.
- صفحة الإدارة تنشئ مستخدمًا بإيميل وكلمة مرور، وتحفظ password hash فقط؛ الويب والبوت يعملان على نفس `ledgerId`.
- تثبيت إعدادات Contabo المطلوبة لإدارة المستخدمين وعزل دفاترهم، مع إبقاء ملفات التشغيل والأسرار خارج Git.
- توسيع اختبارات توازي الويب والبوت:
  - تحويل دينار.
  - تحويل دولار.
  - مصروف.
  - بيع دولار.
  - شراء دولار.
  - حركة ناقصة.
- تفعيل نوع حركة `دخل` في الويب والبوت.
- جعل حركات الدخل/التصحيح التي لا تحتاج مصدرًا تتجاوز خطوة `من` في الويب والبوت.
- إضافة تمييز بصري أولي لحركة الدخل.
- قصر ربط `مشروع / أصل` على حركات الدخل والمصروف فقط، ومنع ظهوره في التحويل وبيع/شراء الدولار.
- توحيد فرق المطابقة في core مشترك مع `diffDinar` و `diffUsd`.
- تقوية metadata المرفقات: نوع ملف، حجم، رابط/مسار، وحد حجم.
- نقل إيقاف الحركات المتكررة إلى core بدل منطق inline في الواجهة.
- نقل بناء التنبيهات إلى core قابل للاختبار.
- إضافة فلاتر السجل: بحث، نوع حركة، حالة.
- إضافة فلترة السجل بالحساب.
- إضافة تنبيه حركة كبيرة وتنبيه تكرار محتمل من core قابل للاختبار.
- إضافة snapshot قبل ترحيل legacy وجعل النسخ المحلية تعمل حتى لو كانت قائمة النسخ القديمة فاسدة.
- نشر الويب على GitHub Pages وتشغيل الواجهة الخلفية والبوت على Contabo؛ يعاد التحقق الحي بعد كل إصدار.
- تحديث Command Center بعد تحقق الروابط والسيرفر.

- جعل حذف المرفق إخفاءً آمنًا مع بقاء أثره، ومنع حذف الملف قبل نجاح حفظ حالة الدفتر.
- تحسين قائمة مراجعة البوت بالتقسيم إلى صفحات مع ثبات الصفحة بعد القرار.
- اختصار إنشاء حساب «شخص أو جهة» بإزالة السؤال ذي الخيار الواحد، وإلزام تسمية مكان الكاش أو المصرف.

## نتائج التحقق المؤكدة

- فحص عزل API بعد جلسات الإيميل/كلمة المرور، ومنع العبور بين دفاتر المستخدمين.
- `pnpm test`: نجح، `212` اختبارًا في `30` ملفًا.
- `pnpm typecheck`: نجح.
- `pnpm lint`: نجح.
- `pnpm build`: نجح.
- `pnpm audit --prod`: لا توجد ثغرات حزم معروفة.
- فحص التشغيل العام نجح للصحة، وتسجيل الدخول، وقراءة دفتر مراقبة مستقل.
- خدمتا API والبوت نشطتان على Contabo، ومراقبة دورة Telegram كاملة لم تسجل خطأ جديدًا.
- فحص Playwright للهاتف والكمبيوتر: لا يوجد horizontal overflow أو clipping في الإدخال/السجل، وفلاتر السجل ظاهرة، وربط المشروع/الأصل لا يظهر في التحويل.
- فحص Playwright بعد فلتر الحساب: 4 عناصر فلترة ظاهرة، ولا يوجد overflow أو clipping على الهاتف والكمبيوتر.
- فحص Chrome/CDP للهاتف بعرض 390px: الإدخال، الأرصدة، الحركات، المراجعة بدون horizontal overflow.
- فحص الهاتف بعرض `390px`: لا يوجد امتداد أفقي في الدخول والإدخال والأرصدة والحركات والمراجعة وإنشاء الحساب.
- اختبار فعلي محلي لإنشاء حساب مصرفي بالدولار، ظهوره في الأرصدة، وإعادة النموذج إلى بدايته.
